# EV-046 — Owner rulings, call protocol batch (design round 7 reactions, 2026-08-06)

Provenance: ground-truth (owner verbatim, design gate session ②, round 8 instructions).

## Verbatim

> "Two things: ask the user for whether they want a follow up. If a caller drops a call, booking holds immediately expire. Also, index callers by phone number. For known callers, add a "is this {person}?" to the greeting, and include context on what they previously called about. This requires call summaries to be computed, and those summaries are what's loaded in, not the full previous transcripts. For the booking flow, the agent should ask for the person's name, negotiate a date, ask if the number the caller is calling from can be used for a callback (the agent should have the caller's number injected into context) or if they're prefer a text (also these are only if a preference isn't already recorded. If one is, just clarify, "and I can {action} you back at this number, right?" The one case where you'd a full transcript is if a caller suddenly hung up (meaning you'd have to mark this differently) so the next call (if within a 1 hour timespan) can be resumed as-is. A few other cases to handle; a person booking for someone else, or booking for multiple people (or booking themselves for multiple visits - depends on practice policy). Also, handling multilingual clients (check audgent model capabilities wrt to this, and we may need to do more design for this feature). Remember, pretty much everything here is just a default, and the practice may override these or how the call flow should be handled. Also, the summaries are then another background task (grading being another). Depending on the state or on office policy, we may need to include a message that the call is being recorded or that they're speaking to an AI, which should be at the end of the greeting, or otherwise cleverly designed in. This also heavily depends on the practice, but by default let's leave it off. Tool calls are another area to be careful - in general these should resolve in milliseconds, but if not, the agent should be able to gracefully acknowledge such as "one sec". Also note, a single call may handle multiple matters for the caller."

## Consequences

1. **Follow-up ask in the booking flow** (→ PKT-04): after negotiating a date the agent asks whether the caller wants a follow-up — "can I use this number for a callback, or would you prefer a text?" — with the caller's number injected into the agent's context. Asked only when no communication preference is recorded; if one is, the agent just clarifies: "and I can {action} you back at this number, right?"
2. **Dropped call → holds expire immediately** (→ PKT-02, PKT-04): no TTL wait; caller drop releases all of that call's booking holds at once.
3. **Callers indexed by phone number** (→ PKT-16, PKT-04): known number → greeting includes "is this {person}?" plus context on what they previously called about.
4. **Call summaries, not transcripts** (→ PKT-05): prior-call context is loaded from computed summaries, never full transcripts. Summaries are a background task, like grading.
5. **Sudden-hangup resume** (→ PKT-04, PKT-05): a sudden hangup is marked distinctly on the call record; the one full-transcript load is when the same number calls back within 1 hour — the call resumes as-is.
6. **Booking variants** (→ PKT-04): booking for someone else, for multiple people, or oneself for multiple visits — handled per practice policy.
7. **Multilingual callers** (→ PKT-04, capability check EV-011): audgent's provider surface is multilingual-capable (STT: Deepgram/Google/Sarvam/Azure/Speechmatics/Gladia; TTS: ElevenLabs/Google/Azure/Sarvam/Camb.ai; realtime: OpenAI Realtime/Gemini Live/Ultravox — EV-011/AC-04, AC-06), but no language-detection or mid-call language-switching feature is cataloged, and the default MiniCPM5-1B local LLM's multilingual quality is unverified. More design needed — open item.
8. **Everything is a default** (→ PKT-03, PKT-04): practices may override these behaviors and how the call flow is handled.
9. **Recording/AI disclosure** (→ PKT-04, PKT-03): per state or office policy, a "this call is being recorded" / "you're speaking with an AI" message at the end of the greeting or otherwise cleverly designed in. Default: off.
10. **Tool-call latency** (→ PKT-04): tool calls should resolve in milliseconds; when one doesn't, the agent gracefully acknowledges ("one sec").
11. **Multi-matter calls** (→ PKT-04): a single call may handle multiple matters for the caller.
