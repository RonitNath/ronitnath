Chose **a stating interface over an explaining one**, because every surface this platform builds is
generated by an agent from a spec, and an agent writing a screen reaches for prose to justify what it
just drew. The owner named the result as "a broader pattern of AI built interface preference I
greatly dislike." Left as a review comment it would be re-violated by the next generated surface; as
a decision it is a constraint the build can be checked against.

**The rules the build must now follow.** All five are enforced in `design/penpot/lib.js` so a board
cannot quietly break one, and all five apply to the shipped product, not only to the boards.

| Rule | What it forbids |
| --- | --- |
| **The interface states; it does not explain** | Any line that justifies the design, reassures the reader, or narrates what just happened. A screen says what the owner's data is. Rationale belongs in this repo. |
| **Five type sizes** | `28 / 21 / 17 / 15 / 12` and no others. The rejected file had nineteen; size variance was doing work that colour and space should do. |
| **Larger, never heavier** | Weight 600 does not exist in the system. 400 is default; 500 lifts an active control or a column header. A title is a title by size and typeface. |
| **No eyebrows** | No small label stacked above a bigger thing — greetings, section kickers, uppercase field labels over inputs, count captions above the number. The number reads first; its label is a footnote under it. |
| **No route chips** | The URL does not appear in the corner of a screen. Routes live in DEC-011. |

**Two consequences taken deliberately, because they look like omissions and are not:**

1. **The healthy stream state renders nothing.** A standing green `LIVE` badge tells the owner only
   what he already assumes, and the whole of DEC-006 is that he must find out when it *stops* being
   true. `reconnecting` and `disconnected` render loudly; `live` renders silence. This makes PKT-13's
   "a disconnected stream is visible" the *only* stream affordance, which is stronger than pairing it
   with a badge that is always on.
2. **Status is coloured text, not a chip.** A badge survives only where the state is the row's
   subject — the event index's lifecycle column — never as an annotation on every row.

**What this does not decide.** The residual contrast between the display face (Fraunces) and the body
face (Newsreader) at identical weight is a typeface property, not a weight setting; it is left as it
is, and running titles in Newsreader too — which retires the display face — stays the owner's call.

**What would change this**: a surface where the absent explanation demonstrably costs the owner an
error he would not otherwise have made. Then that one line earns its place, as data about state
rather than as commentary — and the rule holds everywhere else.
