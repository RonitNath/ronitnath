## Stack (fixed)

- Next.js 15 App Router, TypeScript strict, React 19, Server Actions for
  commands, Route Handlers only for `/healthz`, `/api/*` bearer routes and
  OIDC callbacks. Tailwind 4 with the OKLCH tokens as CSS variables; no
  component library.
- PostgreSQL 17 via `pg` + Drizzle ORM; SQL migrations in `drizzle/`
  generated by drizzle-kit and applied by `pnpm db:migrate` (never at boot).
  One DSN `DATABASE_URL`; production dials `127.0.0.1:5000` (per-node HAProxy
  in front of Patroni `internal-ha`). Local dev: `compose.dev.yaml` runs
  `postgres:17` on `127.0.0.1:5433`.
- Package manager pnpm; Node 24 in the image (`node:24-alpine`, standalone
  output). Runtime image is built on the target host or pulled from GHCR
  `ghcr.io/ronitnath/ronitnath`; deploys are manual (`docker compose`).
- Tests: vitest for units, Playwright for golden flows against a real dev
  server + dev Postgres. `pnpm gate` = typecheck + lint + vitest + build.
- Observability: `/healthz` (no-store, 200 + db round-trip), structured
  JSON logs to stdout. No OTel in this cut.

## Product contract

Four audiences, and the boundary between them is the whole authorisation
model. Every page/action names the tier it needs via one of four server
helpers (`requireVisitor|requireMember|requireSubjectPerson|requireOrgOperator|
requireOperator`); there is no per-route guard to forget. The path says which
object a page is about: `<user>` is a person's public id and `<org>` an
organization's handle (fleet-conventions §1). `/app`, `/org/<handle>` and
`/platform` are permanent redirects to the three above.

| tier | who | surface |
|---|---|---|
| visitor | anonymous | `/` landing (orbiting sky), public pages, `/auth`, `/links/<token>`, `/e/<slug>` guest pages |
| member | signed-in person | `/u/<user>` — profile, identities/factors, sessions, held people, invitations |
| organization operator | admin/owner in an org | `/o/<org>` — members, groups, invitations, shares |
| platform operator | `operator` relation | `/o/isoastra` — parties, identities, matches, sessions, audit, disable |

Identity (owner ruling 2026-09-05):
- **Ronit signs in only via OIDC at `auth.isoastra.com`** (ZITADEL, Isoastra
  org, app `ronitnath`). The callback accepts exactly the allowlisted email
  `ronit@isoastra.com` (env `OIDC_ALLOWLIST`), links it to the person seeded
  as platform operator, and refuses every other subject. No password factor
  is ever created for that person.
- **Everyone else has local accounts**: email + password (argon2id), email
  verification and password reset by mail (useSend SMTP, env `SMTP_URL`;
  dev = console transport). Sessions are opaque 256-bit tokens stored as
  SHA-256, cookie `rn_session` HttpOnly/Secure/SameSite=Lax, 30-day sliding.
- Held people (no login) exist from invitations/events and can later claim an
  account through a personal link (ConfirmMatch = self-link merge).

Model (from the kernel report, simplified for Postgres):
`party(kind person|organization|service)`, `person`, `identity(person, source,
subject)`, `factor(identity, kind email|password|oidc, ...)`, `session`,
`link(token_hash, kind, target, expires)`, `organization`, `group`,
`relation(subject_kind, subject_id, verb, resource_kind, resource_id)`,
`resource` registry, `document`, `event`, `event_invite`, `rsvp`,
`audit(id bigserial, actor, command, target, payload jsonb, at)`.
Public ids are type-prefixed (`p_ i_ o_ g_ r_ s_ l_ e_`) base64url of an
AES-128-encrypted internal id, key from env `ID_KEY`; internal integer ids
never leave the server. Relation vocabulary: `viewer<commenter<editor` on
documents; `member<admin<owner` on organizations and groups; `contact`;
`operator`; `host`/`invited`/`attending` on events. Every command is one
transaction with an audit row inside; authorisation ends in
`allows(ctx, want)` whose last clause is "…or a platform operator".

## Rules for legs

- Read this file, then `docs/design.md` (copied from legacy at R0), then only
  what the brief names. Never `git checkout`; the repo is jj-colocated — use
  `jj` (`jj describe -m`, `jj commit -m`, `jj bookmark set`, `jj git push -b`).
- Feature modules under `src/features/<name>/` own schema, commands, queries,
  components and tests. Root files ≤200 lines; production files warn at 350,
  fail at 600 without a written reason. No `utils/` dumping ground.
- The UI states, it does not explain: no eyebrows, no quips, five type sizes,
  no status pills (a state is a word in its own colour), radius 0.25rem,
  borders over shadows, both themes authored.
- Every command: one transaction, audit row, typed input via zod, uniform
  decline (404 for unreachable, never 403 that leaks existence).
- Visual work is done only with agent-browser screenshots actually viewed,
  both themes, desktop + phone width. `pnpm gate` green before reporting.
- Behind the edge `request.url` is the container's bind address (`0.0.0.0:3140`),
  never the public host. Absolute URLs — redirects, mail links, and the OIDC
  `redirect_uri` openid-client rebuilds from the URL it is handed — come from
  `src/lib/request-url.ts` (`PUBLIC_ORIGIN`); `request.url` may only be read
  for path and query (`grep -rn 'request\.url' src` at review). Libraries that
  check `instanceof` across routes (openid-client) are `serverExternalPackages`.
  Auth is verified only by a completed login through the public edge with the
  ZITADEL human `support@isoastra.com`, temporarily allowlisted and removed.
- Report: what shipped, what was verified (commands run), what was left out.
