Platform admin

Twenty-one stories about operating a deployment, read against the tree at rb-x0, turned into requirements and drawn.

Open the diagrams (tldraw) →

The requirements in full — file:line evidence, command shapes, audit shapes, config keys, one falsifiable acceptance test each — are docs/stories/platform-admin-requirements.md. The implementation legs are docs/stories/platform-admin-legs.md. This page is the condensed table and the frame index.

Five findings

These are not one story's business, and every leg inherits them.

  1. God mode is eight commands wide, not twenty-six. is_platform_operator is consulted by disable, enable, revoke, revoke_link, revoke_session, transfer, the merge rulings and the OIDC commands. The other eighteen authorise against ownership or membership alone, so an operator cannot set_role inside a tenant, cannot invite, cannot share. The ruling says full authority over every party and resource.
  2. SetRole cannot grant the operator relation, though cmd/mod.rs:361 says it does: it writes membership rows and takes a container, and platform is not one. So story 2 has no implementation at all today, not a partial one.
  3. A disable deletes what an enable cannot restore — and misses the one thing that needs it. Sessions, tokens and codes go and should; invitation links are untouched, so a disabled person's outstanding invitations still claim.
  4. An operator's ruling is invisible to the person it was about. The audit query is keyed by actor, so a revocation done to you by somebody else is not in your list.
  5. There is no product concept in the tree at all, and the router is built once at boot — which is the whole difficulty of story 5.

The two requirements the arc is judged on

B5.4. Three voters up. Toggle a product on node 1. Every node answers differently within two seconds, and pgrep shows the same three pids before and after. A leg that cannot produce that transcript has not delivered runtime product enablement, whatever else it built.

D12.2. A table-driven test over every command name: the actor holding nothing is declined, the actor holding platform:* #operator is not, and every success wrote an audit row naming them. The test enumerates the command list, so a command added later with no operator path fails the build rather than being noticed in a review.
